## 直接接入工程或单文件

用户给出可访问的工程目录、文件路径或附件时，先按问题分析实际材料，无需用户先运行示例、初始化目录、登记算例或复制整个模型。只有“开始”且未给定工程时才运行教学示例。路径不可访问时准确指出缺项，请用户附文件或打开相应目录。

收到目录时先查看工程入口及与问题有关的文件。收到单文件时从该文件开始：DAT 核对软件方言、单位、INCLUDE、井控与日程；OUT 核对终止、警告和实际控制；SR3 核对可读字段、井名和时段。配套文件在授权范围内再读取，同名仅为候选；输入目标、实达工况和缺失证据分别说明。附件不足时先完成可以完成的分析。

已有项目接口沿用原接口。需要持续保存且允许写入时，在已授权工作区按工程分别创建或复用独立的记录目录，记下源工程位置；不要为登记就移动原件或混用其他工程的记录。用户指定只读时仅作本次分析。单独安装 skill 时如缺少 CLI，使用工程现有接口或保存人类可读交接页。

先读当前工程的 AGENTS.md 和上下文入口，通过已登记的编号找到母体。已有项目有自己的接口时沿用它。新项目可使用配套仓库中的 harness.py；单独安装本技能时也可使用项目自己的清单。

接手已有研究时，先从研究者要回答的问题定位基准。配套仓库可用 `current <role>` 找到已选版本和选择理由，未建立角色时再读交接页。用能改变研究决策的观测来选对照，例如相同注气政策下先查各层实注量。参数缺失时记录来源和候选假设。软件求解、工程验收、物理解释与预测标签各自产生证据，按实际完成的部分报告。

修正的结论若进入报告或机器读取接口，把同一版本写回生成源、角色和交接页。历史快照保留。角色选择需有研究者决定或已有授权，执行者不因文件更新日期更晚而自动提升版本。

用户要求“先判断、给我审阅”时，交付假设、可比条件和判据。用户明确说“开始运行”后，在派生目录试算、核查、再运行共同研究时段。要求“停”时记下已完成的算例、尚未核实的结果及恢复位置。用户说“打不开”或“结果里看不到”时，在其指出的具体文件和软件入口复现，分别核对求解器和图形界面。

每轮交付注明母体、修改量、实际运行状态、经验证的物理量和下一项待判问题。面向研究者使用油藏工程名称，算例编号放在名称后。对导师的材料保留能解释选择的数据和图，不夹杂代写建议。

- 使用 WinProp、GEM、Results 或 CMOST 时，按需要读 [软件验收](references/native.md)。
- 设计机理对照、判断历史拟合或准备预测标签时，读 [证据与判据](references/evidence.md)。
- 遇到审阅、追问、返工或版本交接时，读 [沟通与复核实例](references/collaboration.md)。

## 默认保存与按任务读取

接手、继续或切换任务时，先执行 `python harness.py --project study context` 看主题、算例和当前角色。将 study 替换为实际研究目录。只读取与本轮工作有关的主题，例如 `context fluid`、`context history-match` 或 `context report`；需要追溯纠正经过才加 `--history`。打开已选文件前运行 `current ROLE` 做完整性核查。旧研究没有主题时，按需读取已有交接页，并在首次实质进展后建立主题。

默认在交付前记录本轮实质变化：新增或修正经核实的结果、用户明确的反馈或决策、交付物变化、阻塞、暂停及恢复点。按主题执行 `checkpoint TOPIC --base N --kind KIND --summary "当前已知状态" --next "下一项动作"`。N 取上次读取的修订号，新主题为 0；按需附 `--case ID` 和 `--evidence 项目相对路径`。保存完整、简短的当前主题摘要及仍相关的依据。收到纠正时说明修正了什么、依据是谁的指示或哪份数据，区分待验证解释与已核实结果。多主题变化分开保存。再读一次该主题，核对修订号与恢复动作；失败就报告具体原因。重复查询、措辞闲聊不写快照，用户要求只读时尊重该范围。遇到版本冲突先重读并合并，保留过往修订。算例登记和基准选择直接反映在主题总览中；checkpoint 不授予运行权限，也不切换基准。

一般研究目录中的记录留在本地，保存工作所需摘要和证据位置即可，不复制聊天全文、凭证或个人信息。只装了 skill 而没有 harness.py 时，优先使用项目已有的等价读写接口；否则告知用户如何接入完整工具包。
